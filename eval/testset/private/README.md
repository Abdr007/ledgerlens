# Real invoices — scored locally, never published

Everything in this directory except this file and `labels.example.json` is
gitignored, deliberately.

The corpus in the parent directory is **generated by this repository**: one
renderer, one layout, four vendors, all AED, and the offline parser's patterns are
written against the captions that renderer prints. It establishes that the
pipeline is correct end to end on the format it was built for. It cannot say
anything about invoices this repository did not author.

Real invoices answer that, and they cannot be committed to do it. One carries a
vendor, a street address, a tax registration number, line items, amounts and the
recipient's own name — and `labels.json` restates every one of those in plaintext,
so committing the labels publishes the contents even where the document itself is
ignored. This repository is public, and git history is not a place to discover
that afterwards.

So real documents live here, and `run_eval.py` picks them up if present and scores
them as a **separate population**. The two are never averaged: a single accuracy
figure spanning documents this repository rendered and documents it did not would
describe neither.

## Adding one

1. Drop the file in this directory — PDF, PNG or JPEG, same limits as an upload.
2. Add an entry to `labels.json` here (create it; copy the shape from
   `labels.example.json`).
3. `python eval/run_eval.py`

Ground truth is what a careful human reads off the page. Where a field genuinely
is not present, use `null` — that is a real answer, and the harness scores it as
one. Do not guess: a wrong label makes a correct extraction look like a failure,
which is worse than not having the document at all.

`expected_anomalies` is usually `[]`. Fill it only when you know the document
should be flagged — a genuine duplicate of another file in the set, or an amount
far outside that vendor's normal range *within this set*. The detectors compare
against the history they can see, so an expectation that depends on invoices you
have not added will be recorded as a miss.

## What not to do

- **Do not run `--regenerate` expecting it to touch this.** It rewrites the parent
  `labels.json` from the generator. This directory is untouched, but the parent's
  hand-edits are not — which is why real documents belong here rather than there.
- **Do not commit anything here.** The `.gitignore` covers it, but a `git add -f`
  would override that.
